## 1. 静态版与 Flask 版的区别

| 特性 | Flask 版（`app.py`） | 静态版（`static-deploy/`） |
|---|---|---|
| 运行环境 | 需要 Python 服务器 | 纯 HTML/CSS/JS，无需后端 |
| 数据存储 | `data.json` 文件 | 浏览器 localStorage |
| 图片上传 | 存服务器 `static/uploads/` | 转 base64 存 localStorage |
| 后台保活 | 守护线程 ping | 不需要（静态站始终在线） |
| 适合场景 | 自有服务器、需多人协作 | 个人使用、快速分享 |
| 部署平台 | 任意服务器 | Vercel / Cloudflare Pages / GitHub Pages |

> **注意**：静态版数据存在浏览器本地，换浏览器/清缓存会丢失。请定期用后台的「导出数据」功能备份。

## 2. 项目结构

静态版位于 `static-deploy/` 目录：

```
static-deploy/
├── index.html              ← 客户浏览页（入口）
├── admin.html              ← 管理后台
├── login.html              ← 后台登录页
├── default-data.json       ← 默认议程数据
├── vercel.json             ← Vercel 配置
├── wrangler.toml           ← Cloudflare 配置
├── .github/workflows/
│   └── deploy.yml          ← GitHub Pages 自动部署
├── assets/
│   └── app.js              ← 核心数据层 JS
└── uploads/
    ├── logo.png            ← 示例 Logo
    └── cover.jpg           ← 示例封面图
```

部署前先本地预览，确认效果：

## 4. 部署到 Vercel

### 方式 A：通过 GitHub 自动部署（推荐）

1. 把 `static-deploy/` 目录的内容上传到 GitHub 仓库（可单独建仓库，或放在主仓库的子目录）
2. 登录 [vercel.com](https://vercel.com)，点「New Project」
3. 导入你的 GitHub 仓库
4. 配置：
   - **Root Directory**：如果 static-deploy 在子目录，填 `static-deploy`
   - **Framework Preset**：Other
   - **Build Command**：留空
   - **Output Directory**：留空（或填 `.`）
5. 点「Deploy」，等待 1 分钟完成
6. 获得 `https://你的项目名.vercel.app` 地址

### 方式 B：Vercel CLI 命令行部署

```bash
# 安装 Vercel CLI
npm i -g vercel

# 进入 static-deploy 目录
cd static-deploy

# 部署（首次会要求登录）
vercel

# 部署到生产环境
vercel --prod
```

> `vercel.json` 已配置好路由和缓存策略，无需额外设置。

## 5. 部署到 Cloudflare Pages

### 方式 A：通过 Git 自动部署

1. 把 `static-deploy/` 内容推到 GitHub/GitLab 仓库
2. 登录 [dash.cloudflare.com](https://dash.cloudflare.com)，进入「Pages」
3. 点「Create a project」→「Connect to Git」
4. 选择仓库，配置：
   - **Build command**：留空
   - **Build output directory**：如果 static-deploy 在子目录填 `static-deploy`，否则填 `.`
5. 点「Save and Deploy」，等待 1-2 分钟
6. 获得 `https://项目名.pages.dev` 地址

### 方式 B：Wrangler CLI 直接上传

```bash
# 安装 wrangler
npm i -g wrangler

# 登录
wrangler login

# 进入 static-deploy 目录
cd static-deploy

# 部署
wrangler pages deploy . --project-name=agenda-share
```

> `wrangler.toml` 已配置好。Cloudflare Pages 全球 CDN，速度极快。

## 6. 部署到 GitHub Pages

### 方式 A：GitHub Actions 自动部署（推荐）

1. 把 `static-deploy/` 内容推到 GitHub 仓库的**根目录**（或子目录，需调整 workflow 路径）
2. 确认 `.github/workflows/deploy.yml` 已在仓库中
3. 进入仓库「Settings」→「Pages」→「Source」选 **GitHub Actions**
4. 推送代码到 `main` 分支，自动触发部署
5. 等待 Actions 完成（绿色 ✓）
6. 在「Settings」→「Pages」看到地址：`https://用户名.github.io/仓库名/`

> **注意**：如果仓库名不是 `用户名.github.io`，访问地址会带仓库名前缀。需在 `assets/app.js` 中无需修改，但分享链接会自动包含正确路径。

### 方式 B：手动 GitHub Pages

1. 把 `static-deploy/` 内容推到仓库
2. 「Settings」→「Pages」→「Source」选「Deploy from a branch」
3. 选 `main` 分支 / `root` 目录，点「Save」
4. 等待 2-5 分钟，访问 `https://用户名.github.io/仓库名/`

## 7. 数据管理（导入/导出）

静态版数据存在浏览器 localStorage，**不同浏览器/设备数据独立**。如需迁移：

### 导出（备份）
1. 登录后台 → 顶栏点「📤 导出数据」
2. 自动下载 `agenda-data-时间戳.json` 文件

### 导入（恢复）
1. 登录后台 → 顶栏点「📥 导入数据」
2. 选择之前导出的 JSON 文件
3. 数据立即加载生效

### 重置
1. 后台顶栏点「↺ 重置数据」
2. 确认后恢复到 `default-data.json` 默认数据

> **建议**：每次修改完日程后导出一份备份，防止清缓存丢失。

## 8. 常见问题

### Q1：部署后图片不显示？
静态版默认 Logo/封面在 `uploads/` 目录，部署时会一起上传。如果在后台上传了新图片（base64），图片数据存在 localStorage 中，不依赖服务器文件。

### Q2：换浏览器后数据没了？
localStorage 是浏览器本地的，换浏览器/设备需要重新导入数据。用后台的「导出/导入」功能迁移。

### Q3：GitHub Pages 地址带仓库名前缀怎么办？
这是正常的。如 `https://username.github.io/my-repo/`。浏览页和后台的分享链接会自动正确生成。

### Q4：Vercel/Cloudflare 部署后白屏？
检查浏览器控制台（F12）报错。常见原因：
- `default-data.json` 路径不对 → 确认文件在根目录
- `assets/app.js` 404 → 确认 `assets/` 目录已上传

### Q5：可以用自己的域名吗？
- **Vercel**：Settings → Domains，添加自定义域名
- **Cloudflare Pages**：Custom domains，添加域名（需 DNS 托管在 Cloudflare）
- **GitHub Pages**：Settings → Pages → Custom domain

### Q6：静态版和 Flask 版功能有区别吗？
核心功能完全一致（议程管理、34 项配色、主题切换、二维码分享等）。区别仅在于：
- 静态版无「后台保活」开关（不需要，静态站始终在线）
- 静态版图片上传转 base64 存浏览器（Flask 版存服务器文件）
- 静态版数据在浏览器本地（Flask 版在服务器 data.json，多人共享）

### Q7：base64 图片太大导致 localStorage 满了？
localStorage 通常有 5-10MB 限制。建议上传的 Logo/封面图控制在 500KB 以内。如需更大图片，建议用 Flask 版部署到自有服务器。
